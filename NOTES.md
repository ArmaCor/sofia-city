## 30 августа: клонирование голоса завершено, две новые находки по звуку

### Клон голоса — сделано

ElevenLabs Starter оформлен и оплачен (~$6, уже списано). Ключ лежит в
`.env` (`ELEVENLABS_API_KEY=...`, не в git). Клон создан по 11 старым
живым записям (`POST /v1/voices/add`), `voice_id: Y6SPCXkwxzWQMIRK2ptb`.

Для API-ключа права выставлены по минимуму: **Text to Speech → Access**,
**Voices → Write**, всё остальное — **No Access**. С первого раза забыли
включить Voices → Write и словили `401 missing_permissions:
create_instant_voice_clone` — если будет пересоздание ключа, не забыть
оба права сразу.

Генерация: модель **`eleven_v3`** (не `eleven_multilingual_v2` — той
озвучивали только буквы, ниже почему), тег `[warmly]` в начале текста
(теги v3 — небольшие текстовые пометки в квадратных скобках, сами не
озвучиваются, задают интонацию), `voice_settings: { stability: 0.5,
use_speaker_boost: true }` (стабильность у v3 — фактически 3 режима:
0.0/0.5/1.0 = Creative/Natural/Robust, не произвольное число).
`output_format: mp3_44100_128`.

**Важная находка — TTS не умеет одиночные буквы.** Первая попытка:
записать имя буквы отдельным коротким клипом («А», «Эс», «Эм») и
склеивать в рантайме с обвязкой (как было со старыми живыми записями).
И `eleven_v3`, и `eleven_multilingual_v2` на такой ультракороткий текст
без контекста предложения галлюцинируют лишние звуки («ОФ», «МэВ», «БэВ»
вместо «О», «Эм»). Решение — не изолировать букву вообще: генерировать
**целую фразу целиком** на каждую букву («София, помоги Ковшику
выкопать котлован в форме буквы А!» одним файлом). В контексте
предложения буква выговаривается нормально. Архитектура в `voice.js`
из-за этого поменялась: было `VOICE_TEMPLATES` (обвязка + `null` под
букву) + `LETTER_FILES`, стало `LETTER_PHRASE_FILES` — просто словарь
«ключ фразы → буква → готовый файл».

Заодно укоротили `win`-фразу: было «Ура! Буква X готова! Смотри, какой
дом вырос!», стало «Ура! Буква X готова!» — старая версия звучала часто
(копка быстрая) и не совпадала с текущей простой геометрией домика-
заглушки (куб с пирамидой), Владимира это раздражало.

Не тронуто (осталось на всякий случай, но сейчас не актуально): скрипты
генерации (`clone-voice.mjs`, `generate-all.mjs`, `generate-full-letter-
phrases.mjs` и т.д.) остались только в scratchpad-директории сессии, в
репозиторий не попали — при следующей необходимости сгенерировать что-то
ещё нужно будет написать заново (логика простая: `findEnvKey()` читает
`.env`, дальше `fetch` на `/v1/text-to-speech/{voice_id}`).

**Не забыть:** отменить подписку Starter (Billing → Cancel) после того,
как весь голос доведён до финального вида — см. «Что дальше» в CLAUDE.md.

### Заикание в начале озвучки на iPad — найдено и починено

Симптом: на реальном iPad первая фраза (и не только) начиналась с
заикания/щелчка, хотя сами mp3-файлы при прямом прослушивании (не через
игру) были чистые — значит дело было в коде проигрывания, не в записи.

Root cause, найден по логу `#voice-debug` (см. ниже про панель): при
`unlockAudioFiles()` код запускал `play()` на всех 11 файлах разом (так
и должно быть — iOS требует синхронного вызова в жесте пользователя), но
ЖДАЛ до 2 секунд, пока каждый файл либо реально начнёт играть, либо явно
откажет, и только тогда ставил на паузу. На слабом iPad часть файлов
реально декодировалась и играла (пусть с громкостью 0) все эти секунды —
и это совпадало по времени с началом первой настоящей фразы, слышалось
как заикание.

**Фикс, часть 1:** ставить `pause()` сразу же, синхронно, не дожидаясь
ответа `play()` — тогда декодирование обрывается мгновенно. Это ожидаемо
рождает `The operation was aborted` в логе на каждом файле — это не
баг, это ровно то, что должно происходить.

**Фикс, часть 2 (побочный эффект первого фикса):** после резкого обрыва
`play()` через `pause()` тот же самый аудио-элемент (он потом
переиспользуется из пула для настоящего проигрывания той же фразы)
переставал слать событие `ended` при реальном проигрывании — ловилось
только аварийным 8-секундным таймаутом в `_playSequence`. Лечится
вызовом `a.load()` сразу после `pause()`+`currentTime=0` при unlock —
по спецификации `load()` принудительно сбрасывает внутренний конвейер
элемента в чистое состояние перед повторным использованием.

**Отладочная панель `#voice-debug` — ещё раз доказала свою пользу.**
Именно по её логу (с точными таймстампами и текстом ошибок) диагностика
заняла один цикл гипотеза → проверка, вместо гадания. Не убирать, пока
Владимир явно не скажет, что она больше не нужна.

## Звук: путь от «не работает» до «работает» (хронология)

Заняло много итераций, потому что несколько независимых проблем
накладывались друг на друга и маскировали друг друга. Итоговый список
причин — ниже, но важен и порядок: каждая находка открывала следующую.

### 1. Формат m4a не читался на iPad Safari — КОРНЕВАЯ причина большинства
   звуковых багов

Все звуковые файлы были в `.m4a` (AAC). На реальном iPad (Safari 15.6)
`<audio>` падал с `Failed to load because no supported source was found`
— **на каждом без исключения файле**, при этом `Content-Type` сервер
отдавал корректный (`audio/mp4`). На Маке (десктопный браузер) при этом
всё «работало» — но втихую откатывалось на синтез речи, что маскировало
проблему: казалось, что где-то баг в логике, а на самом деле НИ ОДИН
реальный аудиофайл вообще не мог загрузиться.

**Решение:** переконвертировать всё в **mp3** (`libmp3lame`). После этого
`Content-Type: audio/mp3`, и файлы наконец начали проигрываться.

**Урок:** когда фикс за фиксом не помогает и картина каждый раз новая —
скорее всего, чинится симптом, а не причина. Точку в этой истории
поставил не очередной фикс, а **добавление видимого лога прямо в игру**
(см. ниже) — как только увидели точный текст ошибки браузера, причина
нашлась за одну проверку.

### 2. Кеш GitHub Pages (10 минут) — правки звука не долетали

`Cache-Control: max-age=600` на статике GitHub Pages. Файлы вроде
`start.m4a` не меняли имя при обновлении содержимого (в отличие от
JS/CSS, у которых Vite сам добавляет хеш в имя) — браузер мог годами
отдавать старую версию под тем же адресом. Заодно выяснилось: «полностью
закрыть игру и открыть заново» на iPad **не** сбрасывает HTTP-кеш — это
разные уровни кеширования.

**Решение:** версия — **в имени файла** (`start-v5.mp3`), не в URL-параметре.
Бампить суффикс `-vN` при каждой замене содержимого.

**Отдельно:** сначала пробовали версию через `?v=3` в адресе — тоже
похоже мешало на старом Safari при разборе формата (не доказано железно,
но после перехода на versioned-имя-файла проблема ушла и не возвращалась).
Вывод: для `<audio src>` на iOS Safari лучше вообще избегать `?query` —
класть версию в имя.

### 3. Гонка состояний между «разблокировкой» и первым реальным
   проигрыванием

Первая версия `unlockAudioFiles()` использовала тот же пул audio-элементов,
что и реальное проигрывание. Разблокировка файла `start.m4a` и
одновременный реальный вызов `voice.sayThen('start', ...)` иногда
накладывались — разблокировка ставила элемент на паузу и обнуляла ровно
в момент, когда он должен был зазвучать по-настоящему. Результат: полная
тишина на самой первой фразе.

**Решение:** дождаться полного завершения `unlockAudioFiles()` (через
`onDone`-колбэк) и только потом озвучивать первую настоящую реплику.

### 4. iOS Safari: `play()` должен быть вызван СИНХРОННО с жестом — и это
   касается каждого элемента отдельно

Самая коварная находка. Реальный текст ошибки (увидели только благодаря
отладочной панели):

```
The request is not allowed by the user agent or the platform in the
current context, possibly because the user denied permission.
```

Это НЕ «пользователь отказал» в бытовом смысле — это стандартный отказ
Safari, когда `HTMLAudioElement.play()` вызван не в тот же синхронный
тик, что и клик/тап. Мы сначала сделали разблокировку **по одной, через
цепочку `.then()`** (полагая, что так бережнее к слабому iPad) — и
получили: срабатывает только САМЫЙ ПЕРВЫЙ файл в очереди, все остальные
(вызванные из `.then()` предыдущего, то есть уже вне исходного жеста) —
`NotAllowedError`.

(Ранее ошибочно решили, что «11 одновременных `play()` перегружают старый
iPad» — это было неверное толкование зависаний, которые на самом деле были
из-за проблемы №1 (m4a никогда не грузился, элемент бесконечно висел в
ожидании, которое не наступит). После перехода на mp3 стало ясно: дело не
в количестве, а в тайминге относительно жеста.)

**Решение (текущее, рабочее):** запускать `.play()` на **всех** файлах
**синхронно, одним проходом цикла** внутри обработчика клика — то, что
каждый из промисов разрешится (успех/ошибка/таймаут) уже потом, неважно.
Это стандартный паттерн разблокировки аудио на iOS (тот же, что использует
Howler.js). См. `voice.js` → `unlockAudioFiles()`.

### 5. `SpeechSynthesisUtterance.onend` срабатывает раньше конца звука

На этом Safari `onend` у синтеза речи — ненадёжный сигнал, срабатывает
до того, как реально доигран звук. Из-за этого окно награды выскакивало
на середине фразы. Решение: не полагаться на `onend` для расчёта
таймингов вообще, только `onerror` (настоящий сбой) + собственный таймер
по расчётной длительности текста (`Math.max(1800, text.length*110)+600`).
Актуально только для synth-фолбэка — у реальных mp3-файлов используется
надёжное нативное событие `ended`.

### 6. `silenceremove` может съесть часть речи, а не только тишину по краям

Первая попытка обрезать тишину по краям записей (`silenceremove` с
`stop_periods=1`) на многосоставных фразах приняла ПАУЗУ МЕЖДУ
ПРЕДЛОЖЕНИЯМИ за конец записи и обрезала всё, что после — потеряли
половину текста молча (длинная фраза 8.6с превратилась в 2.2с).

**Решение — безопасный «разворот-трюк»:** обрезать тишину только с начала
через `silenceremove` в режиме `start_periods` (он никогда не выбрасывает
то, что идёт ПОСЛЕ найденной речи), затем `areverse`, повторить обрезку
(теперь она снимает то, что было концом), затем `areverse` обратно.
Внутренние паузы не трогаются никогда — потому и безопасно.

```
silenceremove=start_periods=1:start_threshold=-38dB:start_duration=0.05,
areverse,
silenceremove=start_periods=1:start_threshold=-38dB:start_duration=0.05,
areverse
```

### 7. Дёрганность/рывки в 3D — было из-за количества отдельных объектов

Ранняя жалоба: «всё квадратное, дёрганое и не плавное». Часть («квадратное»)
— осознанная заглушка (Ковшик собран из простых коробок, заменить на
модели с Kenney.nl — отдельная задача). Часть («дёргано») — реальный баг:

- Забор из 30 отдельных `Mesh` → **`InstancedMesh`** (2 инстанса вместо 30).
- Поворот экскаватора зависел от количества кадров в секунду, а не от
  времени (`heading += diff * 0.18` каждый кадр) → сделать через `dt`:
  `heading += diff * Math.min(1, dt * 11)`.
- Точки-подсказки и кубики котлована рисовались отдельными `Mesh` —
  десятки-сотни объектов на кадр. Решение — тоже `InstancedMesh` на
  штрих буквы, что заодно позволило вернуть частую, плавную сетку
  кубиков без роста нагрузки на GPU (см. `task-dig-letter.js`,
  `_revealTrench`/`_growTrench`).
- Тени `1024→768`, `devicePixelRatio` ограничен `1.5` вместо `2`.

## Голос: запись и обработка (текущий пайплайн)

1. Запись — iPhone, приложение «Диктофон», по фразе на файл.
2. Перенос на Мак — AirDrop (когда работает) → падает в `~/Downloads`.
   Диктофон называет файлы по геолокации («Цветочная улица», «Цветочная
   улица 2», ...) — **порядковый номер соответствует порядку записи**,
   проверяется по длительности (`afinfo`), не глазами.
3. Обработка `ffmpeg` (поставлен через `brew install ffmpeg`):
   - обрезка тишины по краям — см. пункт 6 выше (разворот-трюк);
   - EQ против «гнусавости» телефонного микрофона:
     `highpass=f=130, equalizer=f=300:g=-7, equalizer=f=600:g=-4,
     equalizer=f=2500:g=4, equalizer=f=7000:g=4` (версия v5, усиленная —
     первая версия v4 с более слабыми числами не решила проблему на слух
     Владимира: «глухо/гнусаво как и раньше»);
   - `loudnorm=I=-16:TP=-1.5:LRA=11` — ровная громкость между клипами;
   - вывод: mono, 44100Hz, `libmp3lame`, 96kbps.
4. **Статус на конец сессии:** даже после усиленной EQ (v5) голос всё ещё
   звучит глухо/гнусаво на вкус Владимира. Следующий шаг — не EQ третьей
   итерацией, а либо переснять иначе (мик подальше ото рта, другая
   комната), либо (текущее направление) — клонирование голоса.

## Клонирование голоса (ElevenLabs) — план и API (само клонирование доведено до конца 30 августа, см. запись выше)

Владимир хочет не диктовать каждую новую фразу вручную: обучить клон
голоса на уже записанных 11 фразах, дальше генерировать любой новый текст
этим голосом через API.

- **Instant Voice Cloning недоступно на Free-тарифе** — несмотря на то что
  общий веб-поиск (см. ниже) утверждал обратное, актуальный экран
  тарифов ElevenLabs на момент проверки показывает клонирование только
  начиная с **Starter, $6/мес**. Верить актуальному скриншоту с сайта, а
  не тому, что написано в статьях — тарифы меняются часто.
- План (согласован с Владимиром, ещё не выполнен): оформить Starter на
  один месяц → сгенерировать голосом-клоном текущие фразы + с запасом на
  будущие буквы/задания (30 000 кредитов/мес — с большим запасом) →
  сохранить mp3 в `public/assets/voice/` → Владимир отменяет подписку
  (Billing → Cancel) до конца оплаченного периода. Игра от ElevenLabs при
  этом никогда не зависит в рантайме — только на этапе генерации файлов.
- **API-ключ никогда не должен попасть в код игры** (клиентский JS публичен
  на GitHub Pages) — только в локальный `.env`/терминал на время генерации.
  `.env*` добавлен в `.gitignore`.
- API (проверено по актуальной документации docs.elevenlabs.io):
  - Клон: `POST https://api.elevenlabs.io/v1/voices/add`, заголовок
    `xi-api-key`, `multipart/form-data`: `name` (обязательно), `files`
    (один или несколько сэмплов). Ответ: `{"voice_id": "...", ...}`.
  - Озвучка: `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}`,
    JSON `{text, model_id, voice_settings}`. Для русского рекомендован
    `model_id: "eleven_multilingual_v2"`. Ответ — **бинарный mp3 напрямую**,
    не JSON.
  - Разумные `voice_settings` для тёплого дружелюбного голоса (не из
    доки, эмпирическая рекомендация): `stability: 0.45`,
    `similarity_boost: 0.78`, `style: 0.25`, `use_speaker_boost: true`.
  - Ошибки: 401 `{"detail":{"status":"invalid_api_key",...}}`, 401/429
    `{"detail":{"status":"quota_exceeded",...}}`.
- **Статус:** выполнено 30 августа — ключ получен, клон обучен, файлы
  сгенерированы и задеплоены. Реально использованная модель — `eleven_v3`
  (не `eleven_multilingual_v2`, как предполагалось здесь изначально) и
  другие `voice_settings` — подробности и почему в записи выше. Отмена
